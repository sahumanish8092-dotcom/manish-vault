MANISH VAULT 3.0 – SECURITY STATUS

IMPLEMENTED IN THE CURRENT SOURCE
- Failed PIN attempts, persistent cooldown and activity log.
- Offline Recovery Key and Forgot PIN workflow.
- Separate encrypted Decoy Vault, including decoy PIN rotation without replacing the decoy encryption key.
- Manual last-known location capture after runtime permission, stored locally.
- User-triggered share of a theft alert; no automatic data transfer.
- Local theft-response flag, emergency lock, and temporary decrypted-preview cleanup.
- RAM/app-heap and storage dashboard.

NOT CONNECTED / FUTURE WORK
- Remote lock/wipe and automatic notifications need a properly deployed authenticated backend and owner-device pairing.
- SIM-change monitoring and camera-based intruder capture need separate compatibility, privacy and permission design; they are not silently activated.
- Encrypted cloud backup, biometrics, push notifications and battery diagnostics need further implementation and device tests.

SAFETY
- No hidden camera/microphone recording, background tracking, automatic SMS or unauthenticated remote wipe.
- Location is read only after the user taps the location control and grants permission.
- Recovery Key is shown once. If both PIN and Recovery Key are lost, encrypted data is unrecoverable.
